Additional Material

Download buttons and a contents view for course material stored beside your videos.

Libraries

The plugin only looks in the libraries ticked here.

Downloads

Users without it see the button disabled. This is the permission Jellyfin's own Download button uses.
How long a download has to start after the button is pressed.

Where material comes from

  • additional-material.zip in a series (course) or season (section) folder
  • <video file name>.material.zip beside an episode (lesson) or movie

Show material from lower levels on

On a course or section page, the button then lists the archives below it, with links to each lesson.

Icons

Button style

Used for the plus in the two-color style. Jellyfin's own accent is #00A4DC.

Contents view

A zip inside an archive (for example a lab pack) can then be opened in the Contents view and its files downloaded one by one.

Download everything

One zip with all the material the picker lists, each archive unpacked into a folder by section and lesson. It follows "Show material from lower levels on" (Appearance), and holds only what the user can see.
A smaller one downloads at once, put together as it goes. A larger one is prepared on disk first (the picker shows its progress), and its download can be resumed. 0 prepares every one first.
The next download of the same material is then served from disk, and can be resumed. Kept and prepared ones are in the plugin's data folder, used only while the material is unchanged, and removed after 7 days without a download.

Build archives

Uses the helper script's rules: lesson files go with their lesson, section and course files with their section and course, and programs, scripts and documents with macros or embedded code are replaced by a note. Courses that already have archives (made by hand or by the script) are left as they are.
Otherwise an archive is built the first time someone downloads it. Archives are rebuilt when their files change.

Where built archives go

One-file material

A lesson whose only material is one PDF downloads as that PDF.
Only when zipping makes it noticeably smaller: the plugin checks a sample of the file, and never zips formats that are compressed already (images, Office files, video, zip).

Rules

When the plugin builds archives, rules decide which files are left out (adverts, shortcuts, clutter) and which folders hold a lesson's attachments. They are the helper script's rule files: turn one off, edit it, or add your own. An edited built-in rule replaces the original until you reset it.
The rule file format ↗
The saved rules that are on, for the helper script: unzip them into a folder and run it with --no-default-rules --rules <folder>.

The file must be named after its id, so the id is what you see in the list. Its [[test]] cases run when you check it; a rule whose tests fail cannot be used. Changes take effect when you save.

VirusTotal

Programs, scripts and documents with macros are replaced by a note in built archives. With a VirusTotal API key, each one is looked up by its SHA-256 fingerprint, and the note says what VirusTotal's antivirus engines make of it. Only the fingerprint is sent: files are never uploaded.

Getting a key (free)

  1. Create a free VirusTotal account, and confirm the email it sends: virustotal.com/gui/join-us ↗
  2. Signed in, open your profile menu (top right) and choose API key, or go straight to: virustotal.com/gui/my-apikey ↗
  3. Copy the key, paste it below, press Test key, then Save.
The free (public) API allows 4 lookups a minute and 500 a day, and VirusTotal's terms allow it for non-commercial use only. Each file is looked up once and the answer remembered (for 30 days; a day when VirusTotal did not know the file), so a library uses little of that.
Leave empty to turn lookups off. Stored in the plugin's settings on the server, which only administrators can read.
4 is the free API's limit. Raise it only with a premium key.
Instead of replacing them by a note. Off by default: no engine flagging a file is not proof that it is safe. A file VirusTotal has never seen is always replaced by a note.
Lookups run in the background after a re-read; when an answer arrives, that course's archives are planned and (with background building) built again.

Folder index

The plugin remembers which folders hold material, re-reading them after every library scan. Re-read now after adding or changing zips.

Built archives

Rebuilds every archive the plugin builds, from the files on the disk now. Archives made by hand or by the script are never touched.

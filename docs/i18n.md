# Translating Additional Material

Only English ships today. Every word a person reads is already in a catalog, so adding a
language is a file (or two) and a pull request. No code changes and no build steps. This page is
everything you need; the short version is beside each catalog (`README.md`).

## The two catalogs

| | file | what it covers | who sees it |
|---|---|---|---|
| **Web** | `src/Jellyfin.Plugin.AdditionalMaterial/Web/i18n/<code>.json` | the button, the picker and contents view, and the plugin's settings page (165 strings) | everyone using Jellyfin's web client |
| **Notes** | `tools/i18n/<code>.json` | the `.REMOVED.txt` note that replaces a program or macro document in an archive (9 strings) | people who open a downloaded archive |

Most languages only need the first. Translate **Web** first: it is what people see every day.

**Notes are used by the helper script only, for now.** The script writes notes in the language
you give it (`--language de`, or from `LANG`). Archives the plugin builds itself always get English
notes, because the server has no one reader whose language it could pick. A notes translation is
still worth having for anyone who runs the script, and it is ready if the plugin ever gets a
setting for it.

## Starting a language

1. Pick the code: a language tag, **in lower case**: `de`, `fr`, `pt-br`, `zh-hans`. The file
   name is the code: `de.json`, `pt-br.json`. Lower case matters: the script looks for exactly
   that name, and the tests refuse anything else.
2. Copy `en.json` to `<code>.json` in the catalog's folder.
3. Translate the **values**. Never change a key: `dialog.download` is an address, not a word.
4. Leave out anything you are not sure of, or not done with yet. **A missing string shows in
   English, never blank**, so a partial translation is useful from the first line, and you can
   send it in several pull requests.

```zsh
python3 tools/i18n_status.py de      # what is still missing, with the English for each
```

## How the plugin picks a language

The web client asks for the language it is displayed in: the user's **Display language** in
Jellyfin (user menu → Settings → Display), or the browser's language when that is left on
automatic. A regional tag falls back to its language, then to English, string by string:

```
pt-BR  →  pt-br.json, then pt.json, then en.json
```

So a `pt-br.json` only needs the strings that differ from `pt.json`, if a `pt.json` exists. Each
user sees their own language; nothing is set on the server.

The script does the same for notes: `--language pt-BR`, or `LANG=pt_BR.UTF-8`, tries `pt-br.json`,
then `pt.json`, then English.

## Rules for the text

**Keep every `{placeholder}`**, spelled exactly as in English: `{size}`, `{count}`, `{name}`. They
are filled in when the text is shown. Move them wherever your grammar needs them; word order is
yours. A placeholder that is missing, renamed or added fails the tests.

```json
"dialog.downloadAll": "Download all (.zip, {size})",
"dialog.downloadAll": "Alles herunterladen (.zip, {size})",
```

**Text, not HTML.** Strings are inserted as plain text, so `<b>` or `&amp;` would show literally.
Write `<folder>` if you mean the characters `<folder>`.

**Notes keep their line breaks.** In the notes catalog, `\n` starts a new line in a plain-text
file. Keep lines under about 95 characters, as the English does, so the note reads well in any text
editor.

**Keep these as they are:** file names and patterns (`additional-material.zip`,
`<video name>.material.zip`, `.REMOVED.txt`), command-line options (`--no-default-rules`,
`--allow-executables`), `SHA-256`, `VirusTotal`, `API`, `TOML`, and `#00A4DC`.

**Short labels stay short.** The settings sidebar (`config.nav.*`) and the buttons in the contents
view (`dialog.download`, `config.rule.edit`) have little room. A long translation wraps rather than
breaking anything, but a short word reads better.

### Words with a fixed meaning

The plugin calls Jellyfin's series, seasons and episodes **courses, sections and lessons**, because
that is what they are in a training library. Pick one word for each and keep to it everywhere.

| English | means |
|---|---|
| additional material | the files that come with a course: slides, labs, PDFs, code |
| archive | a .zip holding a lesson's, section's or course's material |
| course / section / lesson | Jellyfin's series / season / episode |
| contents view | the list of files inside an archive |
| left out | not put in a built archive at all, by a rule (an advert, a shortcut) |
| removed | replaced in the archive by a note saying why (a program, a macro document) |
| rule | one of the files that decide what is left out |
| re-read | the plugin listing the library's folders again |

### Plurals

English needs two forms, so a few strings come in pairs: `dialog.file` ("1 file") and
`dialog.files` ("{count} files"), `button.countOne` and `button.count`. The plugin chooses by
"one, or not one". Languages with more forms (Polish, Russian, Arabic) cannot be exact with that:
use the form that reads best for most numbers, and say so in your pull request. Proper plural
rules can come later if a language needs them.

### Right-to-left languages

Untested. The strings will display, but the dialog and settings layout have not been checked
mirrored. Please send the translation anyway, and say what looks wrong.

## Checking your work

Three steps, from quickest to most thorough.

**1. The checker.** It lists what is missing and what is wrong: keys English lacks (a typo),
placeholders that differ, a bad file name. It needs only Python 3.

```zsh
python3 tools/i18n_status.py         # every language
python3 tools/i18n_status.py de      # one language, string by string
```

**2. The tests.** The same checks, as the project's CI runs them (Python 3.11 or newer):

```zsh
python3 -m unittest discover -s tests
```

**3. See it.** For notes, build archives from the sample library and read one:

```zsh
python3 tools/planner-compare/fixtures.py /tmp/am-lib
python3 tools/make_additional_material.py /tmp/am-lib --apply --language de
find /tmp/am-lib -name 'additional-material.zip' -exec unzip -p {} '*.REMOVED.txt' \; | head -20
```

For the web strings, build the plugin and start the test server (see **Building** and
**Testing** in the README): `tests/integration.sh out` leaves one running at
`http://127.0.0.1:18096`, with throwaway accounts in `/tmp/am-test/creds`. Set your user's
display language, open a course, and open the plugin's settings page. The server lets browsers
keep the strings for an hour, so **reload without the cache** (Ctrl+Shift+R, or ⌘⇧R on a Mac)
after changing a file.

## Sending it

One pull request per language is easiest to review. Put the language's English name and its own
name in the title ("German (Deutsch)"). If you are a native speaker, or are not, say so; either
is welcome, and it tells a reviewer what to look at.

When English strings change in a later version, `python3 tools/i18n_status.py <code>` shows what
a translation is missing. Strings that were removed from English fail the tests until they are
removed from the translation too, so a stale string never hangs around.
